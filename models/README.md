# 人物与动作资源

## 切换人物与适配

在网页「帮助与设置 → 演示人员设置」中选择形象，再点击「切换形象」。人物列表来自 `/api/avatars`，文件通过 `/api/avatars/{name}` 的固定白名单读取，不开放模型目录。原 `/api/avatar` 默认入口继续保留。本次切换不清空对话和业务流程，刷新页面仍使用默认 Lumine。

| 人物 | 适配方式 |
| --- | --- |
| Lumine_companion | 已有口型、眨眼绑定；补充微笑，使用专属待机与配套头发/衣服动画 |
| Lumine | 加载时为已有面部形变补齐五种嘴型、双眼/单眼眨眼和微笑；原始文件不改写 |
| Anaxa、Ashveil、Klee、Lohen、Odette、Ratio | 保留原生口型、眨眼、视线和 Spring Bone 物理配置，复用标准人形骨骼待机，跳过 Lumine 专属原始节点动画 |

所有人物在放松手臂后计算真实包围盒，重新设置相机、缩放范围和全身视角；通过 VRM 标准骨骼重定向场景动作，保留语音优先的嘴型控制。仅 Lumine 应用已有肤色材质校正，其他人物保留原材质。加载新人物期间保留旧形象，过期下载会释放，加载失败可以重新选择。

验证：8 个模型均检查了骨骼、表情绑定及资源接口，浏览器逐个确认全身显示，并逐个完成「谢谢」回复、致谢动作和返回待机，无浏览器错误。自动化测试为 Python 43 项、前端 39 项通过；覆盖列表选择、Lumine 表情补齐、通用待机隔离、过期加载和失败保留旧人物。未对每个人物与每个动作的全部组合逐帧检查穿模。

- `characters/`：3D 人物。`Lumine.vrm` 是原始文件，仅移动目录；`Lumine_companion.vrm` 是网页默认版本，增加双眼眨眼、元音口型和视线角度配置，原几何、贴图二进制数据保持不变。
- `animations/`：动作。`Lumine_idle.blend` 是通过 Blender MCP 制作的可编辑工程，打开 `DigitalHelper_Idle` 场景，按空格预览。`Lumine_idle.json` 是网页读取的采样动作数据，8 秒循环、30 FPS，16 个人形骨骼及 75 个头发/衣服骨骼轨道。
- `../tools/animation_authoring/build_idle.py`：Blender 制作与导出脚本。需要先使用 VRM 插件导入原始人物，骨架名为 `Armature`、脸部网格名为 `U_Char_1`；在 Blender 中执行，输出上述工程、采样动作和适配人物副本。

头发与衣服使用骨骼关键帧摆动，不是实时布料碰撞模拟。网页端对四元数进行球面插值；眨眼由独立计时器每约 2.2–4.8 秒触发，保证播放其他动作时仍可眨眼。

眼睛响应鼠标/触摸在屏幕中的位置，平滑跟随，离开窗口或结束触摸后回正。未启用摄像头或真人追踪。开启“减少动态”会暂停待机骨骼动画，并让视线回到正前方；眨眼保留。

默认资源通过 `/api/avatar` 和 `/api/animations/idle` 读取。JSON 轨道中的 `bone` 表示 VRM 标准化骨骼绝对旋转，`node` 表示原模型节点相对初始局部旋转的增量，仅用于匹配的 Lumine 模型；上传其他人物不会套用这组专属轨道。


## 对话场景动作

| 动作 | 自动触发情况 |
| --- | --- |
| greet_1.vrma | 你好、您好、在吗等问候 |
| explain_1.vrma | 原健康咨询、服务讲解；网页入口仍为 explain |
| explain_2.vrma | 左手摊掌讲解，与 explain_1 同属讲解场景，随机播放 |
| alert_1.vrma | 查看健康预警及待处理的提醒 |
| booking_1.vrma | 进入预约或重新进入预约引导场景 |
| confirm_1.vrma | 完成或取消预约、确认提醒 |
| thanks_1.vrma | 谢谢、感谢、辛苦 |
| wink_1.vrma | 眨个眼、wink、你真可爱、你真棒 |

所有场景动作统一命名为 `场景_正整数.vrma`，例如 `greet_1.vrma`、`greet_2.vrma`。编号从 1 开始，不带前导零；预览和配套数据使用相同前缀，如 `greet_1.preview.mp4`、`greet_1.secondary.json`，工程为 `Lumine_greet_1.blend`。待机工程及数据继续使用 `Lumine_idle` 命名，Blender 工程内部 Action 名称保持不变。

前端通过 `GET /api/animations` 获取七个白名单场景的版本目录；每条带动作的回复都会触发一次随机选择。有多个版本时排除该场景上次实际播放的版本；只有一个版本时正常重复播放。首次进入页面只播放自然待机，预加载不会影响随机选择。健康提醒和预约流程优先，夸奖不会中断办理步骤。

版本通过 `/api/animations/{name}/{variant}` 加载，例如 `/api/animations/explain/explain_2`；按版本缓存，配套头发/衣服数据通过同地址追加 `/secondary` 读取，只用于默认人物，长度按数据自身时间轴计算。缺失配套数据仍播放身体动作；身体动作失败则回到待机。旧接口 `/api/animations/{name}` 继续返回编号最小的版本，旧问候配套接口也保留。

以后添加 `explain_3.vrma` 或其他白名单场景的编号动作后，刷新网页即可发现，无需改代码或重启后端。只放入对应 `.vrma` 即可；预览、Blender 工程不会被作为动作资源公开。需要人物专属摆动时可另附同名 `.secondary.json`，格式须与现有数据一致。

每个场景动作播放一次，以约 0.3 秒过渡进入和退出，结束后恢复待机骨骼及位置。语音始终控制五种发音嘴型：所有场景及手动预览都会过滤动作中的元音和下颌轨道，身体、微笑和眨眼继续播放。`FULL_EXPRESSION_ACTIONS` 仍暂停自动眨眼和视线控制，但不暂停口型。朗读时临时解除表情的 overrideMouth 压制，在每次模型更新后恢复原设置。嘴型间约 60 毫秒平滑切换，静音和播放结束清零；没有时间轴时使用音量驱动，浏览器播报使用近似口型。头发和衣服轻摆继续运行。“减少动态”会停止当前场景动作并禁止自动触发，语音口型保留。动作加载失败不影响对话。

手动载入的 VRMA 同样播放一次后返回待机；旧请求不会在更换人物或切换场景后突然生效。
